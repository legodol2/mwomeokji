# 뭐먹지

집에 있는 조리도구, 입맛, 사는 지역을 넣으면 **근처 마트에서 살 수 있는 재료로 정해둔 예산·기간 안에 먹을 식단과 장보기 목록**을 짜 주는 iOS/Android 앱입니다. React Native(Expo SDK 57).

## 실행

```bash
npm install          # 최초 1회
npm start            # 개발 서버 (QR 코드가 뜹니다)
npm run ios          # iOS 시뮬레이터
npm run android      # Android 에뮬레이터
```

**내 폰에서 보기** — App Store/Play에서 **Expo Go**를 깔고, `npm start` 후 뜨는 QR을 카메라(iOS)나 Expo Go(Android)로 찍으면 됩니다. 폰과 맥이 같은 와이파이에 있어야 합니다.

**설치되는 앱으로 만들기** — 스토어 없이 폰에 직접 설치하려면:

```bash
npx expo install expo-dev-client
npx eas build --profile preview --platform ios      # 또는 android
```

Play 스토어/앱 스토어 제출은 `npx eas build --profile production` → `npx eas submit`.

## 화면

앱을 처음 켜면 **5단계 설정**을 차례로 묻습니다. 한 화면에 하나씩만 물어봅니다.

| | 묻는 것 |
|---|---|
| 1 | **지역** — 지도를 눌러 핀을 찍거나 `◎ 현재 위치로` 버튼. 찍은 자리를 주소로 바꿔 그 동네 마트를 찾습니다 |
| 2 | **자주 가는 마트** — 그 지역에 있는 곳만 나옵니다. 여러 곳 선택 가능(전체 선택 버튼), 고른 곳 중 **가장 싼 곳**으로 계산합니다 |
| 3 | **집에 있는 조리도구** — 복수 선택. 집에 이미 있는 양념도 같이 체크 |
| 4 | **못 먹는 것** — 없음 / 돼지 / 해산물 / 채식 |
| 5 | **예산과 기간** — 예산, 며칠치, 먹는 사람, 하루 몇 끼. 아래에 "총 10인분, 한 끼 약 9,000원꼴" 이 바로 계산돼 붙습니다 |

끝나면 메인으로 들어갑니다. 화면 위에는 늘 **총액 · 예산 잔액 막대**가 붙어 있습니다.

| 탭 | 하는 일 |
|---|---|
| **메뉴**(메인) | 위에 **입맛**(한식·양식·일식·중식·매운맛), 아래에 조건에 맞는 메뉴가 쭉. 눌러 담으면 장보기가 즉시 다시 계산됩니다. 각 줄의 금액은 **그 메뉴를 한 끼 더 담을 때 새로 사야 하는 돈** — 이미 산 재료를 다시 쓰는 메뉴는 +0원 |
| **식단** | 앱이 알아서 짠 날짜별 끼니표. 끼니를 누르면 인분 맞춘 재료·도구·조리법. 아래 **‘그대로 담기’**로 통째로 장바구니에 |
| **장보기** | *앱이 짠 식단* / *내가 담은 메뉴* 중 골라, 어떤 제품을 몇 개 사면 되는지 마트 동선 순서로. 담을 때마다 체크하면 담은 금액이 올라갑니다 |
| **설정** | 5단계에서 정한 것 전부 + 마트별 총액 비교(‘· 가장 쌈’ 표시) + 처음부터 다시 하기 |

설정·장바구니·장보기 체크는 AsyncStorage에 저장돼 앱을 껐다 켜도 남습니다.

### 담기 → 장보기가 이어지는 방식

메뉴를 담으면 재료를 인원수만큼 곱해 합치고, **파는 단위로 올림**해 개수와 값을 냅니다. 제육볶음을 한 번 더 담아도 앞다리살 한 팩(6,900원)만 늘고 양파·대파·고추장은 0원인 식입니다.

## 계산 방식

낱개가 아니라 **파는 단위**(양파 1.5kg 망, 계란 10구)로 올림 계산합니다. 그래서 재료를 돌려쓰는 조합일수록 싸집니다.

1. 가진 도구·입맛·매운맛·못 먹는 것으로 만들 수 있는 요리를 추립니다
2. 한 끼씩 채워 넣으면서 **"이 요리를 넣으면 새로 사야 하는 팩 값"**만 비교합니다 (이미 산 재료를 또 쓰면 0원)
3. 다양성 가중치 × 반복 상한을 40가지 조합으로 바꿔가며 돌린 뒤, **예산 안에서 요리 가짓수가 가장 많은** 안을 고릅니다
4. 상하기 쉬운 재료를 쓰는 요리를 앞 날짜로 옮기고, 같은 요리가 하루에 두 번 오지 않게 자리를 맞바꿉니다
5. 예산을 넘으면 "며칠치까지 가능한지 / 어느 마트가 얼마 싼지 / 끼니를 줄이면 얼마 주는지"를 숫자로 알려 줍니다

지역은 시·도와 주요 시 이름을 알아보고, 그 지역에 실제로 있는 매장 종류만 후보로 올립니다. 대형마트·창고형·하나로마트·전통시장·동네슈퍼·온라인에 각각 다른 가격 계수가 붙고, 창고형은 용량 2배·단가 14% 할인, 온라인은 4만원 미만 배송비, 제주는 물류비 7%와 배송비 2배가 반영됩니다.

## 위치·지도

`react-native-maps`(iOS는 Apple 지도, Android는 Google 지도)와 `expo-location`을 씁니다. 좌표는 `Location.reverseGeocodeAsync`로 주소를 받아 `시·도 + 시·군·구` 형태로 만든 뒤 `src/data.js`의 `REGIONS` 표와 맞춰 봅니다. 정식 행정명(경상남도·강원특별자치도 등)과 줄임말(경남·강원)을 모두 알아듣고, 못 알아보면 기본 마트 구성으로 떨어집니다.

- 위치 권한은 온보딩에서 한 번 묻고, 거부해도 지도를 직접 눌러 핀을 찍으면 됩니다.
- Expo Go에서는 권한 안내문이 Expo Go 것으로 뜹니다. 직접 빌드하면 `app.json`에 적어 둔 한국어 안내문이 나옵니다.
- **Android 독립 빌드**는 Google Maps API 키가 필요합니다. (Expo Go로 볼 때는 필요 없습니다.)

  > ⚠️ **이 저장소는 공개입니다.** 키를 `app.json`에 직접 적어 커밋하면 그대로 공개됩니다. 다음 순서로 넣으세요.
  > 1. Google Cloud 콘솔에서 **Maps SDK for Android** 키를 만들고, **애플리케이션 제한**을 Android 앱 + 패키지명 `com.mwomeokji.app` + 서명 인증서 지문으로 걸어 둡니다. **API 제한**도 Maps SDK for Android 하나로 좁힙니다.
  > 2. 키는 파일이 아니라 EAS 비밀값으로 둡니다 — `eas secret:create --name GOOGLE_MAPS_ANDROID_KEY --value <키>`
  > 3. `app.json`을 `app.config.js`로 바꿔 `process.env.GOOGLE_MAPS_ANDROID_KEY`를 읽게 하고, 키 자체는 절대 커밋하지 않습니다.
  >
  > 실수로 커밋했다면 파일에서 지우는 것만으로는 부족합니다. **Google 콘솔에서 그 키를 폐기하고 새로 발급**해야 합니다.

## 메뉴 그림

메뉴 옆 그림은 **이모지**입니다. 글자로 저장되고 기기 글꼴(iOS는 Apple Color Emoji, Android는 Noto Color Emoji)이 그리므로, 앱에 담기는 이미지 파일이 없고 저작권·라이선스 문제가 없습니다. 네트워크도 타지 않아 오프라인에서도 보입니다. 바꾸려면 `src/data.js`의 레시피에서 `e:` 값만 고치면 됩니다.

## 가격에 대해

마트별 가격 배율(`src/data.js`의 `MART`)은 특정 마트를 조사한 값이 아니라 매장 유형에 따른 **가정**입니다. 또 마트 실시간 가격 API는 공개된 것이 없어서, **국내 대형마트·전통시장의 통상 판매 시세를 넣은 내장 표**에 위 계수를 곱한 **추정치**입니다. 실제 매대 가격은 행사·산지·시기에 따라 20%씩 움직이니 총액은 여유 있게 잡으세요. 시세를 고치려면 `src/data.js`의 `ING`에서 `p`(파는 단위 가격)와 `pq`(단위 수량)만 손보면 됩니다.
